# Location-based environment

`server/environment.mjs` exports `getEnvironment(location, {signal})` and an injectable `createEnvironmentService({fetchImpl, now, cacheTtlMs, timeoutMs, cacheLimit})` factory. Coordinates are WGS84 `{latitude, longitude}`. Missing/unavailable locations and normalized `freshness: 'stale'` use central Warsaw (52.2318,21.006); explicit invalid coordinates throw a 400 EnvironmentError. Callers that obtain GPS elsewhere must normalize its freshness before calling this service. The browser does this using the shared observedAt snapshot (maximum age five minutes).

`GET /api/environment` uses central Warsaw. Supply both `latitude` and `longitude` to request another location. Responses are no-store; server cache is at most 100 complete responses for five minutes, at approximately 100 m sampling precision (coordinates rounded to three decimal places). The response `location` records the actual requested coordinates and basis; provider-returned `grid` records the actual model cell. Grid cells may be kilometres away. Source timestamps (`validAt`) are distinct from `fetchedAt`. Data over two hours behind or over an hour ahead are marked stale and never cached as a complete response. A new Warsaw date invalidates cached solar times.

The service returns independent `weather`, `air`, `sun` objects with ok/partial/unavailable statuses. Null or failed data remain missing. Provider requests run concurrently with an eight-second timeout; caller cancellation propagates. Failures do not leak provider exception details, and a working component survives failure of another source. Failed/partial responses are retried on the next request rather than cached. `complete` means all requested components are usable and not stale; it does not certify an exact-location measurement.

`environment.js` loads automatically, reads `window.getCityLocation()` and subscribes to `city:location`. It clears previous-location values during loading/error, aborts replaced requests, ignores late responses and refreshes every five minutes or on page visibility. It accepts fresh available snapshots `{status:'available',latitude,longitude,observedAt}`; unavailable, stale or undated snapshots use Warsaw. No location permission is requested by this module. All displayed times use Europe/Warsaw, including DST, via Unix provider timestamps.

The capsule expands to show condition description, model-valid times, freshness, location basis and attribution. Icons cover all documented Open-Meteo WMO codes (including 97), distinguish clear/partly-cloudy day and night, and use an unknown fallback. AQI is explicitly European AQI, not US AQI or the Polish station index. This index is based on modelled pollution rather than a nearby sensor reading.

Provider contracts verified 2026-10-17:

- [Open-Meteo weather API](https://open-meteo.com/en/docs): current temperature, weather_code, is_day; daily sunrise/sunset; timeformat=unixtime and timezone=Europe/Warsaw. Model output, not direct station observations.
- [Open-Meteo air-quality API](https://open-meteo.com/en/docs/air-quality-api): current european_aqi and pm2_5, domains=cams_europe. CAMS ENSEMBLE European model, approximately 11 km resolution. Required Open-Meteo and CAMS attribution appears in the capsule. AQI bands: good ≤20, fair ≤40, moderate ≤60, poor ≤80, very poor ≤100, extreme >100.

The public endpoints require no key. The public service is intended for non-commercial use; evaluate Open-Meteo's commercial terms and quotas before a commercial rollout.

Production chat injects this same server service through `createAssistant({environmentProvider: getEnvironment})`. Every new turn obtains a small source-linked environment snapshot alongside the normalized browser location, without a model tool call or trusting browser-supplied weather. Fresh measured coordinates select `basis: gps`; missing, stale or undated fixes select `basis: central_warsaw`. The model receives component status, source/grid, validAt/fetchedAt and freshness. Provider errors remain explicit context and do not prevent ordinary chat. Prior conversation messages are not rewritten. MCP now searches only events, sports, pitches and routes; weather/air station categories have been removed from its schemas and default searches.

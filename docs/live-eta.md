# Continuous live ETA

The HTTP server starts tracking both municipal vehicle feeds when DATA_API_KEY is configured, before any route request. Each cycle refreshes the current GTFS graph and samples both fleets concurrently. Sampling aims for a 15-second period measured from cycle start; timetable evidence runs separately, so a slow departure endpoint cannot delay the next GPS sample.

For fresh vehicles on every active line, the service queues one representative municipal platform to obtain brigade evidence. A binding requires an exact departure clock, direction and dated GTFS trip. Positive bindings can identify that same trip at another platform; an absent branch or brigade at one platform never proves absence across the line. Branch-specific misses queue their own evidence request. A vehicle still needs observed entries and stationary dwell at two consecutive stops, with an unambiguous same-trip match, before its delta adjusts downstream ETA. A cold server needs these observations; no live value is invented while warming.

Evidence work is FIFO, limited to 12 requests per cycle and four concurrent requests, independently of the two fleet requests. The queue and platform cache each hold at most 512 entries; shared positive associations hold at most 32,768 trip bindings across at most 256 lines. Evidence expires after ten minutes. Failed requests return to the queue with bounded exponential backoff. This fixes the old 100-entry queue/cache churn, repeated per-stop lookups, and timetable requests blocking GPS polling.

Only current per-vehicle point/dwell state and current signed trip deltas are kept in RAM. No GPS history is written to disk. Delta expiry remains three minutes. Existing GTFS files are schedule data, not vehicle history. Route searches consume the shared model without restarting or narrowing it. Both map responses filter stale positions before selecting the nearest 40.

`liveModel` diagnostics expose pending/cached/shared evidence, request failures and timestamps, current tracking counts, and the last fleet poll time/error. Missing or stale city data, ambiguous brigade matches and newly started tracking continue to produce schedule-only estimates.
